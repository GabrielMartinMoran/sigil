# Design history

These records preserve earlier designs and the evidence behind them. They are
not installation instructions or a list of current configuration options.

## Read the original decisions

Use a record when you need the rationale or an alternative that was considered:

- [Original core boundary](core-boundary.md): the service extraction target,
  original phases, risks, and command/event design.
- [Context and cache optimization](context-optimization.md): an earlier
  multi-level reduction proposal, exploratory measurements, and acceptance
  criteria.

For current behavior, use the [architecture overview](../architecture/README.md)
and [context reference](../internals/context.md). A historical test count,
module path, or proposed setting must not be treated as current without checking
its implementation.
